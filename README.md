# Chatbot

可嵌入多個平台的 chatbot：提供選單導覽與客服對話，以獨立 repo 開發、交付容器映像檔，由各平台自行部署。第一個接入的平台是 prediction。本資料夾為規劃文件，排期為**提案**。

| 文件 | 內容 |
| --- | --- |
| [`requirements.md`](./requirements.md) | 需求：目標與範圍、使用者角色、功能需求、非功能需求、限制條件、架構決策依據 |
| [`mvp.md`](./mvp.md) | 最小可行方案：第一版的定案、功能模組、選單規則、資料表、成功標準、取捨 |
| [`roadmap.md`](./roadmap.md) | 未來可擴充方向：階段總覽、各階段功能、MVP 已預留的擴充點 |
| [`schedule.md`](./schedule.md) | 實作排期：為何獨立成 repo、stage 定義、各 sprint 工作與工時、驗收點、外部依賴、待拍板事項、風險 |

## 結論一覽

- **形態**：獨立服務＋插件 Widget，交付容器映像檔；每個平台各自部署一套、自行決定升級時間，資料庫與帳號不共用；Widget 由每套 chatbot 自己提供
- **接入**：平台簽標準 JWT、公開 JWKS，不限技術棧（Python 平台可用 `scitw_auth`）；chatbot 是 core-python-lib 的消費端，本身不放進函式庫
- **第一版**：選單導覽、工單與即時對話（客服在線即時對話、離線留言）、客服端、管理後台；只接 prediction（forum、voting）
- **使用者**：未登入可使用導覽；開工單需登入
- **客服**：各平台各自處理，客服與營運帳號存在各自那套 chatbot 裡
- **平台專屬規則**：例如 prediction 的「不得預測或建議」，第一版只預留掛載位置
- **排期**：6 個 sprint、12 週；人力、啟動時間、即時通訊實作方式尚未決定
